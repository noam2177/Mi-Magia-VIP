## 3. ארכיטקטורת יעד

```
RSVP-app (בסיס: wedding-v1)  ── אתר אחד, Supabase אחד
│
├─ שיווק/הרשמה:  /            נחיתה ראשית + מחשבון     (חדש, מהרפקטור)
│                /start, /thanks
├─ סביבת מארגן:  /w/:token    דמו עד 5 הזמנות → אחרי מקדמה: מלא
├─ אירוע (לקוח): /e/:slug             נחיתת האירוע (קולאז', FAQ, ניווט)  ← דף החתונה
│                /e/:slug/rsvp        מודאל RSVP                          ← rsvp.tsx
│                /e/:slug/admin       אדמין האירוע                        ← admin.index.tsx
│                /g/:token            קישור אורח אישי
└─ דמו ציבורי:   /e/daniel-tomer  (החתונה עצמה כדוגמה חיה)

מודל נתונים: events(id, slug, owner, ...) → invitees.event_id, site_settings.event_id,
             admin_notifications.event_id, RLS לפי חברות באירוע/ארגון.
```

**עקרון:** האירוע הוא יחידת הריבוי. **כל** טבלה נושאת `event_id`. גרסת החתונה הופכת ל"אירוע #1" (slug `daniel-tomer`) בלי לאבד יכולת.

**מרי לא נכנסת לקוד היום.** היא נשארת כמערכת מפעיל נפרדת (Phase 6), עם גשר ליד → ארגון.

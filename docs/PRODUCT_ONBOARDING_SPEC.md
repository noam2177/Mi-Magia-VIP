# מפרט מוצר — הרשמה ציבורית, דמו לפני תשלום, ביט, מייל למפעיל

**מוצר:** הזמנות RSVP (יוזמה E) · **גרסה:** 2026-09-29 · **מאגר:** `danielntomerafter-main`

## 1. מטרה

לאפשר לזוגות/מארגנים **לא רשומים** להיכנס מהנחיתה, לפתוח **סביבת עבודה לפני תשלום**, לשתף בן/בת זוג, לראות איך ההזמנה עובדת (עד **5 מוזמנים חינם**), ולקבל **הצעת מחיר בזמן אמת** לפי כמות אורחים וערוצים (WhatsApp / מייל / טלפון).

**תשלום בשלב 1:** רק **ביט אישי** — **אחרי** שהמפעיל מאשר. המפעיל מקבל **מייל** עם סכום העסקה (מקדמה/יתרה) והוראות **לאן לשלוח קישור ביט** ללקוח. הלקוח משלם; המפעיל מסמן «שולם» במערכת (Hub / אדמין — שלב הבא).

**מביא חבר:** אם חבר שהוזמן בקוד הפניה שילם **מקדמה**, למפנה **זיכוי 50 ₪** (מופחת מהיתרה לתשלום).

---

## 2. מסלול משתמש (זוג / מארגן)

```text
נחיתה (/) → מחשבון מחיר (בזמן אמת) → הרשמה (/start)
  → מייל למפעיל (סכום + ביט) + מייל/מסך תודה ללקוח (קישור לסביבת עבודה)
  → סביבת עבודה (/w/:token) — לפני תשלום מלא
       • חובה: בחירת סוג אירוע
       • עד 5 שליחות הזמנה (סה״כ, כל הערוצים)
       • שיתוף קישור עם בן/בת זוג (אותו token)
       • דמו: אורח רואה דף RSVP אמיתי
  → אחרי מקדמה בביט (אישור מפעיל): הסרת מגבלת 5, ייבוא מרוכז, שיחות טלפון מלאות
```

## 3. מגבלות דמו (מכוון)

| יכולת | לפני מקדמה | אחרי מקדמה בביט |
|--------|------------|------------------|
| כניסה לסביבת עבודה | כן | כן |
| שיתוף עם בן/בת זוג | כן (אותו קישור) | כן |
| בחירת סוג אירוע | **חובה** לפני שליחה | כן |
| שליחת הזמנות (WA / מייל / טלפון) | **עד 5** סה״כ | לפי חבילה |
| ייבוא Excel / מאות אורחים | חסום | פתוח |
| מחשבון מחיר | כן (מסלול מייסדים) | כן |

המגבלה נועדה להוכיח ערך ולדחוף בחירת אירוע + ערוצים, בלי לתת מוצר מלא בחינם.

## 4. מחשבון מחיר (יוזמים ראשונים)

הלוגיקה ב-`src/lib/domain/pricing.ts` — **טבלה אחת** (`FOUNDING_RATE_CARD`) לעדכון על ידי המפעיל בלי לשנות UI.

**קלט:**

- `estimatedGuests` (מספר)
- `channels`: `{ whatsapp, email, phone }` (בוליאני)
- `referralCreditIls` (זיכוי מצטבר, למשל 50 אחרי חבר ששילם מקדמה)

**פלט:**

- `depositDueIls` — מקדמה לגביית ביט (ברירת מחדל במחירון)
- `totalProjectIls` — **התחייבות מינימום** לפי מענים משוערים × ערוצים, עם רף `max(מינימום מוצר, עלות×מרווח)` — לא לפי שליחות
- `estimatedResponses` — מענים לחיוב (אחוז ממוזמנים)
- `balanceAfterDepositIls` — יתרה אחרי מקדמה (לפני זיכוי הפניה)
- `dueNowIls` — מה שמופיע במייל למפעיל כסכום לגביית ביט **עכשיו** (בדרך כלל המקדמה פחות זיכוי)
- שורות פירוט (`lineItems`) לתצוגה ב-UI

**חינם:** 5 ההזמנות הראשונות **לא** מחויבות במחשבון — מוצגות כשורה «דמו — עד 5 מוזמנים».

פרטי המספרים: `docs/PRICING_FOUNDING_USERS.md`.

## 5. מייל למפעיל (אחרי הרשמה)

**נמען:** `OPERATOR_NOTIFY_EMAIL` (שרת בלבד).

**תוכן חובה:**

1. פרטי ליד (שם, טלפון, מייל, סוג אירוע, תאריך משוער, מספר אורחים)
2. ערוצים שנבחרו
3. **סכום לגבייה עכשיו** (`dueNowIls`) + פירוט מקדמה/יתרה
4. **קישור ביט** (`OPERATOR_BIT_LINK`) ו/או **טלפון ביט** (`OPERATOR_BIT_PHONE`) — טקסט להעתקה ללקוח
5. קישור לסביבת העבודה של הלקוח (`/w/:organizer_access_token`) — לבדיקה שלך
6. קוד הפניה של הלקוח (למעקב «מביא חבר»)

**לא** נשלח אוטומטית ללקוח קישור ביט עד שהמפעיל מעתיק/שולח (שלב 1). אופציונלי בשלב 2: מייל אוטומטי ללקוח אחרי אישור.

**שליחה:** `submitOnboardingLead` → `notifyOperator.server.ts` (Resend אם `RESEND_API_KEY`, אחרת לוג + הצלחה עם אזהרה).

## 6. מביא חבר (50 ₪)

1. כל ליד מקבל `referral_code` ייחודי (לשיתוף).
2. בהרשמה: שדה אופציונלי «קוד חבר» → `referred_by_code`.
3. כשהליד **המופנה** עובר ל-`deposit_paid` (המפעיל סימן שקיבל מקדמה בביט):
   - נוצרת רשומה `referral_credits` לליד המפנה: **50 ₪**.
   - מחשבון המחיר של המפנה מפחית `referralCreditIls` מ-`dueNowIls` / יתרה (מינימום 0).
